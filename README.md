## Приложение

**Өлшем** (ASCII: `olshem`) — рабочее место методиста для решений по измеримым результатам тестирования.
Слово связано со смыслом «мера, измерение». Раньше проект назывался **«КартаТем»**: репозиторий
`adilusen/kartatem` и Python-пакет `kartatem` сохранены, переименовано только внешнее название.

Кейс Data-Driven Curriculum, четыре обязательные функции:

1. **Анализ результатов по темам** — средний итоговый тест (post), доля учеников ниже порога, n, форма теста.
2. **Трудные разделы** — флаг с причиной; при малом n флаг не ставится («Мало данных»).
3. **Сравнение учебников** — итоговый результат и описательный прирост post − pre на одной парной выборке.
4. **Распределение часов** — объяснимое предложение при неизменном бюджете, фиксация тем, сценарии,
   сравнение, утверждение, паспорт решения.

> Демо — **синтетические данные**, сгенерированные программой (seed 42): не результаты реальных школ,
> «план математики 6 класса» и два «учебника» условны. Реального пилота не было.

## Центральный сценарий

«Я нашёл слабую тему, проверил основания, зафиксировал часы по темам, которые нельзя менять, сравнил два
допустимых варианта и сохранил своё решение с объяснением».

1. **Обзор → «Открыть демо».** Сразу видна самая слабая тема («Проценты»: итоговый тест 47,8 %, ниже 50 % —
   48,8 % учеников, n = 164) и доступное предложение (+2 ч из «Обыкновенных дробей»).
2. **«Проверить основания»** → экран «Темы»: статус и причина, форма теста, записи в файле и в расчёте,
   результат по каждому учебнику с n.
3. **«Учебники»** — пара, итоговый результат и прирост рядом, одна тема «входной → итоговый» на тех же парах.
   Цвет учебника постоянен; ограничение описательного сравнения видно рядом с графиками.
4. **«Сценарии»** — исходно / предложено / черновик по каждой теме и флажок **«Не изменять»**.
   Сохраните предложение как «Алгоритм», отметьте «Не изменять» у «Обыкновенных дробей» — предложение
   пересчитается в [5, 5, 6, 6, 3, 5] (единственный доступный час: «Пропорции» → «Проценты») — сохраните
   второй сценарий, сравните оба в таблице «Разница Б − А», нажмите «Утвердить» у выбранного.
5. **«Решение»** — статус, паспорт решения (HTML), план (JSON), отчёт (CSV), восстановление из JSON.

Подробный показ на 3 минуты — `DEMO_SCRIPT.md`.

## Запуск на macOS

Нужен Python 3.12 или новее (`python3 --version`). Зависимости закреплены в `requirements.txt`
(`numpy==2.5.4` требует Python ≥ 3.12).

```bash
cd olshem                          # папка из распакованного ZIP
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py               # браузер откроется сам (или http://localhost:8501)
python -m pytest -q                # тесты
```

**Где проверялось.** Автор реализации проверил v4-fixed на Linux/Python 3.13. Независимо на macOS/Python 3.15.0 прошли 182 теста за 22.69 с в ранее установленном окружении. Дополнительные пробы подтвердили сохранение старого контекста, восстановимость текущего утверждённого плана, отклонение повреждённого JSON и отсутствие переноса утверждения. Публичное развёртывание проверяется отдельно.

## Сценарии плана: правила

* **«Не изменять тему»** фиксирует **исходные** часы темы. Зафиксированная тема не бывает ни донором, ни
  получателем; ручной черновик с другим значением не утверждается и не сохраняется (с объяснением причины).
* Пересчёт учитывает фиксации, `min_hours`, `max_delta`, целые часы, достаточность данных (не меньше 15 учеников
  с итоговым тестом) и неизменный бюджет. Доноры и получатели ранжируются по **исходным** результатам, при
  равенстве — по `topic_id`; результат темы после переноса часа не меняется (прогноза нет).
* До **трёх** именованных сценариев в текущей сессии: имя, часы, фиксации и отметка контекста. Переход между
  экранами их не теряет. Сравнение двух: тема, исходно, А, Б, разница, фиксация — без прогноза баллов.
* **Контекст** = исходные файлы + параметры методики + выбранные формы теста. Его смена делает утверждение
  недействительным, а сценарии прежнего контекста помечаются «Другой контекст данных»: утвердить их нельзя,
  пока не нажата «Пересчитать» (предложение алгоритма с теми же фиксациями на текущих данных).
* Утверждается один допустимый вариант (черновик или сохранённый сценарий). Пока форма теста не выбрана хотя
  бы в одной теме, весь план утвердить нельзя.

## Экспорт и восстановление

* **Паспорт решения (`olshem_passport.html`)** — источник и пометка синтетики, формы теста, показатели тем и n,
  исходные/предложенные/итоговые часы, фиксации, причины переносов и причины их отсутствия, бюджет, параметры,
  ограничения. Неутверждённый план помечен «НЕ УТВЕРЖДЁН». Все тексты экранируются. PDF — печатью браузера.
* **План (`olshem_plan.json`)** — версия формата, контекст, параметры и выбор форм, сценарии и **то же решение,
  что показано в блоке «Решение»** (утверждённый план, если он есть, иначе черновик) с его фиксациями. Паспорт,
  JSON и CSV всегда относятся к одному варианту. Если плана нет, а черновик некорректен, кнопка JSON отключена
  с объяснением: невосстановимый файл не выдаётся. Поученичных результатов в файле нет.
* **Контекст сценариев сохраняется:** у каждого сценария в файле свой контекст. Сценарий, созданный до смены
  параметров или формы теста, после восстановления остаётся «Другой контекст данных» — восстановление не является
  пересчётом; утвердить и сравнить его можно только после «Пересчитать».
* **Восстановление:** после перезапуска откройте те же исходные данные (для демо — снова «Открыть демо»),
  затем «Решение → Восстановить план из JSON». Файл разбирается как данные (без eval/pickle) и проверяется:
  чужие данные, неизвестные темы, нецелые часы, выход за границы, сумма ≠ бюджет, нарушение фиксации,
  неверные параметры, повреждённая структура (не те типы, повтор topic_id или имён сценариев, неполный план,
  огромные или нечисловые значения, NaN) — понятная ошибка, текущее состояние не меняется. Восстановленный план становится **черновиком**:
  поле утверждения из файла не используется, утвердите план заново.
* **Отчёт (`olshem_report.csv`)** отражает текущий вариант: утверждённые часы — только у утверждённого плана;
  у неутверждённого — отдельный столбец «Часы в неутверждённом черновике» и статус «Не утверждён».

## Формат файлов

`results.csv` — одна строка = ученик внутри класса × тема × этап (pre/post):

| столбец | смысл |
|---|---|
| `student_id`, `class_id` | обезличенные идентификаторы; ученик = пара `class_id + student_id`; `class_id` уникален в пределах файла |
| `textbook` | условное название учебника |
| `topic_id` | тема (должна быть в `topics.csv`) |
| `stage` | `pre` или `post` (регистр и пробелы нормализуются) |
| `test_id` | форма теста; для сравнения нужен общий внутри темы |
| `score`, `max_score` | баллы и максимум; процент = 100 × score / max_score |

`topics.csv` — общий план группы (не часы учеников): `topic_id, name, hours, min_hours, max_delta`
(целые неотрицательные, `min_hours ≤ hours`). Бюджет = сумма исходных `hours`.

### Формы теста (test_id): как выбираются

Один и тот же выбор формы действует во **всех** расчётах — метрики тем, флаги, тепловая карта, сравнение
учебников, часы, экспорт:

* форма в теме **одна** → выбирается автоматически;
* форм **несколько**, выбор сделан (боковая панель «Формы теста», доступна на всех экранах) → всё считается
  только по выбранной форме; выбор можно менять без повторной загрузки файла;
* форм несколько, выбор **не сделан** → тема помечена «Выберите форму теста»: объединённого среднего нет, флага
  трудности нет, часы темы не меняются, план нельзя утвердить. Остальные темы считаются как обычно;
* предлагаются только формы, реально присутствующие в данных темы; если выбранной формы нет у одного из
  учебников, сравнение сообщает об этом и не проводится;
* только post (без pre): анализ темы доступен, прирост не считается;
* смена формы пересчитывает всё и **сбрасывает** черновик и утверждённый план (они опирались на другой набор
  измерений) — с уведомлением; при загрузке нового источника выбор форм не переносится;
* на экране «Данные» видно, сколько валидных записей в файле и сколько реально использовано в расчёте.

Одинаковый `test_id` — проверка формата, а не доказательство эквивалентности измерения.

Шаблоны скачиваются на экране «Данные» и лежат в `data/`. Разделитель `,` или `;`, кодировка UTF-8 или Windows-1251.

**Блокируют анализ:** нет столбцов, пустые идентификаторы, недопустимый `stage`, неизвестная тема,
конфликтующие дубли (одна запись с разными значениями — мы не усредняем молча).
**Исключаются с отчётом:** пропущенный/нечисловой балл, `max_score ≤ 0`, `score` вне `0…max_score`.

## Что и как считается

* **Тема:** средний итоговый тест (post) и доля учеников ниже 50 % — по ученикам. «Трудная»: средний post < 60 %
  ИЛИ доля ниже 50 % ≥ 40 % при n ≥ 15, иначе «Мало данных».
* **Учебники:** прирост = post − pre у одного ученика, в п.п., по одной форме теста и одному учебнику; ученики со
  сменой учебника исключаются. Нужно ≥ 30 пар и ≥ 2 класса в каждой группе, иначе показывается только post.
  Предупреждение, если входной уровень групп различается больше чем на 10 п.п.
* **Часы:** цель 70 %, доноры от 75 %, шаг 1 час, границы `max(min_hours, hours − max_delta) … hours + max_delta`.
* Все пороги — настраиваемые допущения демо (боковая панель «Параметры методики»), не нормативы.

## Ограничения

* Различие приростов **не доказывает** влияние учебника: группы не случайны, исходный уровень не корректируется,
  доверительных интервалов нет, общего рейтинга учебников нет.
* Распределение часов — **сценарий, не прогноз роста баллов**; решение принимает методист.
* Сценарии и утверждение живут только в текущей сессии; между запусками — через JSON и те же исходные CSV.
  Базы данных, авторизации и ролей нет.
* Реальные данные учеников не загружайте в публичную демо-версию.
