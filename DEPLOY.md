## Шаг 1. Подготовьте папку репозитория

1. Распакуйте `olshem_mvp_v4_fixed.zip`. Внутри будет папка `olshem`.
2. **Содержимое папки `olshem` — это корень репозитория**: `app.py` должен лежать в её корне, а не в подпапке. Проверьте, что в корне есть:
   `app.py`, `requirements.txt`, `.streamlit/config.toml`, папки `kartatem/` (Python-пакет, имя сохранено), `data/`, `tests/` и документы (`README.md`, `DEPLOY.md`, `DEMO_SCRIPT.md`, `STREAMLIT_CONFIG.txt`). Папка `.streamlit` скрытая: в Finder нажмите `Cmd + Shift + .`, чтобы увидеть скрытые файлы.
3. Не загружайте один ZIP вместо исходников и не загружайте родительскую рабочую папку со старыми версиями (`kartatem_mvp_v1/v2/v3`, `.venv`).

## Шаг 2. Обновите существующий репозиторий `adilusen/kartatem`

Репозиторий уже есть, **второй с тем же именем не создавайте** и не переименовывайте его: внешнее название
Өлшем не требует смены имени репозитория или Python-пакета `kartatem`.

### Основной способ: GitHub Desktop (без терминала)

1. Установите GitHub Desktop (desktop.github.com) и войдите в свой аккаунт.
2. **File → Clone Repository…** → выберите `adilusen/kartatem` → укажите папку на Mac → **Clone**.
   Если репозиторий уже склонирован раньше, откройте его и нажмите **Fetch origin / Pull origin**.
3. В Finder откройте склонированную папку `kartatem`. Удалите в ней старые файлы проекта (кроме скрытой папки
   `.git` — её не трогайте; скрытые файлы показывает `Cmd + Shift + .`) и скопируйте туда **содержимое** папки
   `olshem` из архива: `app.py`, `requirements.txt`, `.streamlit/`, `kartatem/`, `data/`, `tests/`, документы.
   Сама папка `olshem` внутрь не кладётся — `app.py` должен оказаться в корне репозитория.
4. В GitHub Desktop проверьте список изменений: нет `.venv`, `__pycache__`, `.zip`.
5. Введите сообщение фиксации, например «Өлшем v4 fixed», нажмите **Commit to main**, затем **Push origin**.

*Названия кнопок GitHub Desktop даны по памяти, а не по официальным страницам выше, и могут немного отличаться.*

### Короткая альтернатива: Терминал

```bash
git clone https://github.com/adilusen/kartatem.git
cd kartatem
# скопируйте сюда содержимое папки olshem (с заменой файлов), затем:
git status                      # проверьте: нет .venv и .zip
git add -A
git commit -m "Өлшем v4 fixed"
git push
```

Git попросит войти в GitHub через браузер или менеджер учётных данных. **Не вставляйте пароли и токены в
файлы проекта и не отправляйте их в чат.**

*Если когда-нибудь понадобится новый пустой репозиторий:* по инструкции GitHub создайте его без README,
.gitignore и лицензии, затем `git init -b main`, `git add .`, `git commit`, `git remote add origin REMOTE-URL`,
`git push -u origin main`.

### Проверка загрузки

Откройте страницу репозитория на GitHub: в корне должны быть `app.py`, `requirements.txt`, `.streamlit/`, `kartatem/`, `data/`. Не должно быть `.venv` и `.zip`. Если репозиторий уже подключён к Streamlit Cloud, новый push обновит приложение — повторно создавать его не нужно (тогда переходите к шагу 4). Если нет папки `.streamlit`, создайте `.streamlit/config.toml` через «Add file → Create new file» по инструкции в `STREAMLIT_CONFIG.txt`. Запомните ветку (обычно `main`).

## Шаг 3. Развернуть в Streamlit Community Cloud (если приложения ещё нет)

1. Откройте share.streamlit.io и войдите через GitHub.
2. В рабочей области нажмите **Create app** (справа вверху). На вопрос «Do you already have an app?» выберите **Yup, I have an app**.
3. Укажите: **Repository** — ваш `…/kartatem`; **Branch** — ветка, в которую загрузили код (`main`); **Main file path** — `app.py`. Поле **App URL** (поддомен на `streamlit.app`) необязательно, его можно изменить позже. Если в списках нет вашего репозитория, введите данные вручную или нажмите **Paste GitHub URL**.
4. Откройте **Advanced settings** → **Python version** → выберите **3.13** (на нём проверена Linux-версия; по документации по умолчанию стоит 3.12) → **Save**. Версия Python выбирается здесь, а **не** строкой в `requirements.txt`. Python 3.15 независимо проверен только на Mac. Если 3.13 нет в списке, выберите ближайшую доступную не ниже 3.12 и запомните выбор.
5. Запустите развёртывание (кнопку запуска документация не называет; это последняя кнопка диалога). Сборка может занять несколько минут. Логи видны справа от приложения, только пользователям с правом записи в репозиторий.

Зависимости (`requirements.txt` в корне) оставлены как есть: `streamlit`, `pandas`, `numpy`, `plotly` и `pytest`, закреплены точными версиями. `.streamlit/config.toml` в корне даёт тему оформления.

## Шаг 4. Проверьте публичную ссылку

1. Откройте ссылку в **приватном окне** браузера, где вы не вошли ни в Streamlit, ни в GitHub.
2. Пройдите путь: **Обзор → «Открыть демо»**: 164 ученика, 3 трудные темы из 6, бюджет 30 ч, 3 ч к переносу → **Учебники** → **Сценарии** → «Утвердить черновик» (статус «Утверждён») → **Решение** → «Скачать паспорт решения (HTML)», «Скачать план (JSON)», «Скачать отчёт (CSV)».
3. Откройте CSV: суммы исходных, предложенных и утверждённых часов должны быть равны 30; пометка синтетики видна.
4. Откройте ссылку **в другом приватном окне или другом браузере**, нажмите «Открыть демо», перейдите в «Сценарии»: статус плана должен быть **не** «Утверждён». Так вы убедитесь, что новая сессия не наследует чужой план.
5. Только после этого подставьте проверенную ссылку в `README.md` (и в материалы подачи, когда они будут обновлены).

## Если развёртывание не удалось

1. Скопируйте **весь** текст лога (панель справа) в файл и пришлите мне — разберём по реальной ошибке, не угадывая.
2. Проверьте: ветка и путь `app.py` указаны верно; `requirements.txt` лежит в корне репозитория; выбрана версия Python не ниже 3.12.
3. Запасной вариант, который вы указали как допустимый правилами: доступный репозиторий (Public) плюс презентация. Проверьте по тексту объявления.
